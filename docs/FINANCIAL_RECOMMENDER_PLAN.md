# 金融产品推荐系统方案

## 一、定位与交付范围

服务退休与临近退休客户，核心任务是帮助客户在保留生活与应急所需的前提下，筛选、比较金融产品。采用 42 个独立产品（报告清单 38 个，另有 4 个银行官网挂牌的整存整取定期存款），保留现有账户与管理员权限，数据库采用 SQLite。产品不是交易执行系统，不接入真实申购、扣款或收益承诺。

客户界面提供产品信息、个人资金计划、适配提醒、同类比较与偏好管理。算法分数、规则证据及异常信息只面向管理员。商品构成为储蓄 14、养老理财 14、保险 8、现金管理 4、其他投资 2。其中 32 个按报告的公开产品清单整理，4 个为银行官网挂牌的个人整存整取定期存款，6 个保留“模拟”名称与标记。模拟商品不能当作真实在售商品，没有购买入口，也不进入投资推荐。退休身份不直接视为个人养老金购买资格。

## 二、客户路径

1. 注册或登录：仅收集称呼、登录账号和密码。客户可输入另一个账号及密码完成切换。
2. 填写资金计划：退休状态、养老收入来源（含“不便提供”）、本次资金、其中的应急预留、最早用款日期、是否接受本金损失、最高风险等级、关注的商品类别。
3. 浏览首页结果：符合当前计划、接近符合（需向销售机构确认）和请谨慎选择，并可查看替代方案。
4. 查看商品封面、收益口径、风险、持有安排、起购金额、来源和资料日期。
5. 收藏以备比较，或明确选择不感兴趣；均随个人账号保存，可撤回。
6. 生活安排变化时修改资金计划，重新获得匹配结果。

已有客户资料保留，不自动改年龄、姓名或收入。未填写新计划时，不用原有默认值假装完成适配；引导客户主动确认。退休状态与收入来源用于理解生活安排，不提高或降低客户风险等级，不贴能力不足标签。个人养老金另记录是否已有账户且经销售机构确认资格、以及本次资金中的账户内可用金额。此项客户自述不替代正式核验。种子账号的已完成计划标记为 `plan_source=seed`，启动时用款日期滚动为当天加其 `preferred_term`；客户保存计划后标记为 `user`，日期由客户计划控制。

## 三、首页与详情

### 符合当前计划

优先展示最多 3 个通过全部硬约束的商品。提供简短的匹配说明，不把“符合筛选条件”等同于官方适当性结论。计划不全、用款日期已过或没有合适商品时展示明确空状态。

### 接近符合

展示最多 6 个通过硬约束、但仍有起购金额、期限或开放状态资料待确认的商品。每项列出 `gaps` 中的具体确认事项；预算不足、锁定期超过用款日、风险或资格不满足的商品不进入此组。

### 替代方案

从本人实际浏览、收藏或主动查找过的、不符合计划的商品出发，展示原商品、冲突原因、同类替代商品与差异。详情页也可主动发起查找。没有合适商品时给出无替代结果。不得改变预算、挪用应急资金或提高客户风险等级。

替代优先在储蓄、养老理财、保险、现金管理、其他投资的同一大类中寻找，并要求替代品风险等级不高于原商品。同类没有合格候选时可提供其他类别，并明确标注类别差异；具体资产类型不同必须提示，且不宣称经济等价、同等收益或同等费用。每个方案包含：

- 原商品与初筛结果；
- 可比较商品，或无结果；
- 风险、持有安排与投资类型差异；
- 收益和费用独立计算的提示。

### 请谨慎选择

只显示本人已实际关注过的商品，主要原因包括风险超出、用款冲突、预算不足、起购不明、开放状态待核实、特定购买资格待确认等。有效负向偏好证据可作为“建议再考虑”的补充，不能称为真实亏损或后悔。

### 可读性

采用中文主导航与操作标签，默认 16 像素基础字号、清晰对比度和不小于 44 像素的主要交互目标，提供 125%、150%、200% 字号。手机端结果纵向排列；弹窗支持键盘焦点循环、关闭后返回原位置。42 张封面使用本地 SVG（Scalable Vector Graphics，可缩放矢量图形）路径、固定宽高比例和加载失败替代内容，不生成伪造历史曲线。

## 四、过滤分层、适当性与到账口径

评估先按三层返回 `tier`：`pass`（符合）、`pending`（资料待确认）和 `hard`（硬约束不通过）。只有 `pass` 进入符合当前计划组，`pending` 进入接近符合组；`hard` 不进入两个推荐组。预算缺口和锁定期超过用款日属于硬约束，不用接近符合组凑数量。

硬约束包括：计划未完成或用款日期已过；模拟商品；风险等级缺失或高于客户上限；客户不能承受本金损失且商品不是普通存款或储蓄国债；起购金额超过相应账户可用资金，或扣除应急预留后没有可安排资金；锁定期超过用款天数；资料披露的到期日已过；明确停售、售罄、发行结束、非开放期等状态；个人养老金的 `pension_lock`（领取条件）未满足、账户资格未确认或账户资金不足；保险的投保条件和现金价值需单独核验；商品存在专属、合格投资者或私募等购买资格要求。普通商品使用“本次资金－应急预留－个人养老金账户资金”，个人养老金商品只使用其账户内资金。

资料待确认包括起购金额未披露、期限未披露，以及资料无法确认当前是否开放申购。商品必须先通过全部硬约束，才会以 `gaps` 列出“请确认起购金额”“请确认最短持有期或赎回到账安排”或“请确认当前是否仍开放申购”等事项。已知的硬性停售、售罄、发行结束或不在募集期状态仍属于硬约束。

到账缓冲和类别偏好属于打分项。目录记录 `term_basis`（`fixed` 固定期限、`min_hold` 最短持有、`open` 随时申赎）、`settlement_days`（自然日到账缓冲）、`value_date`（起息日，可空）；期限档记录 `term_months`。锁定期为募集等待天数加持有期，未来起息日先计入等待；`term_months` 优先按日历月计算，缺失时使用 `term_days`，明确到期日还要取剩余天数中的较大值。默认到账缓冲为：存款和储蓄国债 0 天、货币基金 3 天、理财、基金和保险 7 天。锁定期不超过用款日但剩余天数不足 `settlement_days` 时保留候选并加入到账软扣分，卡片提示到账可能晚于用款日；节假日顺延仍需向销售机构确认。

类别偏好仅影响排序，服务端允许“全部、储蓄、养老理财、保险、现金管理、其他投资”。旧的“基金”和“银行理财”偏好按“全部”处理。大额存单以独立产品计数，`product_variants` 保存期限、起存金额、利率和状态；推荐挑选通过约束的一个期限档，替代可比较所有可用期限档，推荐结果不因期限档重复计数。

评估使用请求当日日期与所存资料；产品状态未连接实时销售系统。完整保留采集日期、原始状态和来源链接，鼓励购买前复核。

## 五、关联规则与匹配算法

### 5.1 行为语义

记录 `view`、`favorite`、`unfavorite`、`avoid`、`restore`、`substitute`，同时保存客户、商品、会话关联和服务器时间。浏览与收藏不能推导出成交；不感兴趣不能推导出亏损或反悔；取消收藏与浏览中断不构成负向证据。恢复关注撤回当前“不感兴趣”状态。同一客户对同一商品每天只记录一次 `substitute`，该行为不计入关联规则的曝光人数。

老行为没有可靠日期时保留空值，不伪造先后顺序。归档目录的行为不参与当前目录算法。产品实际浏览、收藏、明确拒绝与主动查找替代可作为实际接触证据；页面加载推荐结果本身不虚构接触行为。

### 5.2 二元正向规则

将每位有可靠时间行为的客户视为一次观察单位，同一客户反复点击不重复增加人数。正向篮子以真实收藏为依据，历史取消收藏不作为负向反馈。

- 支持度：同时收藏 A 与 B 的用户数 / 有效活跃用户数。
- 置信度：同时收藏 A 与 B 的用户数 / 收藏 A 的用户数。
- 兴趣度：置信度 / 收藏 B 的总体比例。
- 门槛：支持度不低于 0.10，且置信度不低于 0.50 或兴趣度大于 1；至少 3 位共同收藏用户、5 位前件用户和 5 位总体有效用户。

个体触发使用当前仍收藏且未设为不感兴趣的前件，历史收藏用于群体证据计数。

### 5.3 二元负向偏好规则

对 A → 不感兴趣 B，要求收藏 A 在先、接触 B 在后，并在其后明确对 B 表达不感兴趣。支持度按不同用户计数，置信度分母仅包括“收藏 A 后实际接触 B”的用户。基线是全部实际接触 B 的用户中明确不感兴趣且未恢复关注的比例。

- 置信度至少 0.50，且相对接触基线的兴趣度大于 1。
- 至少 10 位前件后接触用户、5 位负向反馈用户，支持度至少 0.10。
- 同一客户的重复事件只计一次；晚于拒绝才收藏 A 不成立；缺少时间不成立；恢复关注撤回负向状态。

这仍是选择性样本中的偏好关联，不作因果推断，也不称为亏损预测。证据不足时不产生规则，不显示人群比例。当前数据稀疏时，允许规则为零。个人明确“不感兴趣”的商品从推荐候选中排除；他人的负向规则只对候选分数施加 `0.15 × 置信度` 的扣分，不单独排除商品。

### 5.4 排序与个人匹配

采用加权曼哈顿距离，先筛选再计算。客户没有合理的目标收益输入，不从风险偏好虚构收益目标。起购金额只做可行性约束，不进入排序距离。

| 特征 | 权重 | 距离口径 |
| --- | ---: | --- |
| 期限与用款安排 | 0.50 | `0.5 × (用款天数 − 锁定天数) / 用款天数`，锁定期越接近用款日扣分越少 |
| 风险等级 | 0.30 | 已退休或临近退休按 `(风险等级 − 1) / (客户上限 − 1)`，风险越低越好；其他状态按 `(客户上限 − 风险等级) / 4`，贴近上限更好 |
| 类别偏好 | 0.20 | 明确偏好不同时为 1，相同时为 0；“全部”时移除该项并按有效权重归一化 |

参与特征的权重重新归一化，相似度为 `1 − 距离`。收益不进入个人适配评分。此距离度量是排序启发式，不代表成功概率或适配百分比。

最终分数为个人相似度，加上最高有效正向规则的 `0.2 × 置信度`，减去最高有效负向规则的 `0.15 × 置信度`，再减去到账缓冲不足的 `0.1` 软扣分。负向规则不能抵消硬约束。符合组最多展示 3 个，接近符合组最多展示 6 个，均按最终分数降序排列。

### 5.5 商品替代距离

候选必须通过同一客户全部硬约束，且未被本人标记为不感兴趣；商品距离不超过 0.60；替代品风险等级不得高于原商品。候选优先保持原商品类别，同类没有合格候选时放宽到其他类别，并在差异中标注类别不同。

替代排序结合个人匹配距离、商品距离、风险等级和商品编号。商品距离比较风险、期限、起购金额、具体投资类型和同口径历史收益；缺失字段不补造数值。收益和费用独立计算，不代表等价或同等收益。

### 5.6 异常与空结果

推荐始终按上述个人分数排序，不启用距离阈值兜底，也不放宽风险、预算、期限、状态、资格或偏好条件。符合组不足 3 个时展示实际数量；符合组为空时展示接近符合组和“可以暂不选择，留好应急金”的说明，两组均为空时只展示说明。计划已过期时返回 `plan_expired` 并提示更新计划。符合组为空且计划有效时，每位客户每天最多写入一条“没有符合当前计划的商品”异常记录。

## 六、持久化与权限

| 表 | 内容 |
| --- | --- |
| `products` | 42 条商品、图片、收益口径、来源、采集日期、模拟标记、保障与资格类别、期限与到账字段 |
| `product_variants` | 同一产品的期限档、利率、起存金额、状态与来源 |
| `customers` | 原客户字段及退休状态、收入来源、目标日期、预留金额、损失承受选择、类别偏好、计划完成标志、`plan_source` |
| `users` | 登录标识、角色、客户关联与加盐密码摘要 |
| `behaviors` | 实际行为、服务器时间，旧时间可空 |
| `product_preferences` | 每客户每商品当前收藏与拒绝状态 |
| `association_rules` | 当前有效规则、统计证据与生成时间 |
| `recommendation_logs` | 推荐/替代/谨慎分组结果、商品快照、评分元数据与时间 |
| `abnormal_records` | 按客户和日期去重的“没有符合当前计划的商品”记录 |
| `archived_behaviors` | 更换商品身份后的原行为与商品快照 |
| `archived_product_preferences` | 更换商品身份后的原收藏与拒绝状态快照 |

采用增量加列与幂等建表。未知老日期保持未知。迁移前备份，导入采用事务回滚。账号和来源商品不能因界面定位变化而重置。数据库连接在每次操作结束时关闭。

密码使用 PBKDF2（Password-Based Key Derivation Function 2，基于密码的密钥派生函数第二版）与随机盐。服务端会话标识关联用户身份，个人接口从会话获得客户标识；如果显式提交另一客户标识则拒绝。客户不能读取他人账户目录、计划、偏好或推荐。管理员可读取管理和诊断信息。普通客户端结果不包含数值评分。

当前服务仅绑定本机，尚未提供公网部署所需的持久会话、密码找回、完整审计保留/删除政策、管理端写入审批和业务资质接入；不得将此版本描述为已上线销售服务。

## 八、验收标准

- 原有账户凭据与客户原字段逐项保留；活动目录恰为 42 个独立产品（报告 38 个、银行官网定期存款 4 个），期限档不凑数，外键检查通过。原目录备份，旧商品偏好归档。
- 42 张本地封面在卡片与详情中加载，图片路径均能读取与解码；图片不包含伪造收益数值。
- 未完成计划、计划过期、资金全部预留、锁定期超过用款日时不产生违规推荐；资料待确认商品只进入接近符合组并列出 `gaps`。不能承受损失时仅保留符合条件的存款与储蓄国债。个人养老金资格、领取条件与资金独立校验。
- 到账缓冲不足只产生软扣分和到账提示；期限按起息日等待、期限月数和到账缓冲核对。
- 符合组按期限 0.5、风险 0.3、类别 0.2 排序；已退休或临近退休用户优先较低风险，其他状态贴近风险上限。没有距离兜底，空结果是有效状态并按客户每天一条记录异常。
- 替代不放宽风险、预算、时间、状态和资格约束；商品距离不超过 0.60，风险不高于原商品，同类无候选时可跨类别并标注差异。
- 时序反转、单用户重复点击、时间缺失与证据不足不能形成负向规则；负向规则门槛为 5 位用户和 10 位曝光，按 0.15×置信度扣分，正向规则按 0.2×置信度加分。
- 同一客户同一商品每天只记录一次替代行为，替代行为不计入规则曝光。
- 收藏与拒绝可撤回、重启后保留；切换账号后互不串用。
- 未登录个人接口拒绝访问，跨用户标识拒绝访问，客户不能访问管理员诊断。
- 浏览器实际完成注册、计划保存、商品查看、收藏、替代、切换；检查桌面、手机和 200% 字号。
- 客户页面无汇报、演示、算法评分界面，无虚构收益与人群统计。
