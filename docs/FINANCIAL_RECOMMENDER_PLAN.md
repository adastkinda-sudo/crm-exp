# 金融产品推荐系统：详细实施计划

## 1. 文档定位

- 项目名称：**金融产品推荐系统**
- 项目类型：金融产品查询与个性化推荐实验
- 文档状态：开发前规划稿
- 目标读者：项目组成员、指导教师和答辩评审
- 数据性质：使用模拟客户、产品和行为数据，不连接真实交易系统

本项目的推荐算法采用“二项关联规则 + 加权最近邻”的组合，并加入金融产品适配约束、异常记录处理和热门产品兜底。系统参考了常见的前后端分层和 API 数据交互方式，但算法组合、数据结构、页面内容、参数和实现均由本项目独立设计。

## 2. 课程要求与验收目标

### 2.1 必须满足的要求

1. 系统主题统一为“金融产品推荐系统”。
2. 推荐对象是金融产品，并且在线页面展示产品图片和基本信息。
3. 后台使用文件或数据库保存客户、产品和行为数据。
4. 实现至少两种推荐算法，重点使用关联算法和最近邻算法。
5. 不同客户或不同同学的推荐内容必须存在明显差异。
6. 关联算法需要先寻找频繁项，再计算两个产品之间的关联。
7. 关联算法不使用购买数量，只判断产品是否出现。
8. 关联规则需要支持置信度阈值和兴趣度大于 1 的筛选条件。
9. 最近邻算法需要进行归一化，并处理超出样例范围的数据。
10. 当最近距离超过设定值（例如 0.6）时，记录新样例候选或异常信息，并使用热门产品作为备用推荐。

### 2.2 项目完成标准

项目完成时，用户可以查询金融产品、切换模拟客户、获取个性化推荐、查看推荐理由和打开产品详情页。答辩时能够展示两种算法的输入、计算过程、结果差异，以及异常客户的兜底推荐。

## 3. 项目范围

### 3.1 本期实现

- 金融产品查询和筛选
- 客户画像展示
- 客户浏览、收藏和购买行为记录
- 二项关联规则推荐
- 加权最近邻推荐
- 风险、预算和在售状态过滤
- 关联与相似度结果融合排序
- 异常客户记录和热门产品兜底
- 推荐理由和算法指标展示
- 产品详情页和后台数据查看页

### 3.2 本期不实现

- 真实开户、支付和购买
- 真实金融行情接入
- 自动生成投资收益承诺
- 真实客户身份认证
- 复杂深度学习模型
- 自动化投资组合交易

这些内容会增加风险和工作量，也不是本次实验验收的重点。

## 4. 核心用户场景

### 场景一：产品查询

用户按照产品名称、发行机构、产品类别、产品类型、风险等级和产品状态筛选金融产品，查看产品图片及基本信息。

### 场景二：个性化推荐

用户选择一个模拟客户，系统根据该客户的风险偏好、投资期限、预算和历史行为生成前三名推荐产品。

### 场景三：推荐解释

用户可以看到产品为何被推荐，包括关联置信度、兴趣度、客户相似度、距离和风险匹配结果。

### 场景四：异常数据处理

输入超出样例范围的客户数据，系统重新计算归一化范围，记录异常字段；如果最近距离仍超过 0.6，则推荐热门产品作为兜底结果。

## 7. 算法设计

### 7.1 金融约束过滤

推荐开始前执行硬过滤：

```text
产品风险等级 > 客户风险承受等级  → 排除
产品最低金额 > 客户可投资金额    → 排除
产品状态不是“在售”              → 排除
```

过滤结果需要保留排除原因，便于调试和答辩解释。

### 7.2 二项关联规则算法

#### 输入

将每个客户或会话转换为产品集合：

```text
客户 A：货币基金、短期理财、信用卡
客户 B：货币基金、养老保险
客户 C：股票基金、长期理财
```

#### 处理步骤

1. 统计单个产品出现频率；
2. 筛选满足最小支持度的频繁产品；
3. 只生成两个产品组成的候选对；
4. 计算支持度、置信度和兴趣度；
5. 根据阈值保存有效规则。

#### 指标

```text
支持度(A → B) = 同时出现 A、B 的记录数 / 总记录数

置信度(A → B) = 同时出现 A、B 的记录数 / 出现 A 的记录数

兴趣度(A → B) = 置信度(A → B) / B 的出现概率
```

建议初始参数：

```text
最小支持度 = 0.10
最小置信度 = 0.50
有效兴趣度 > 1
```

有效规则采用以下条件之一：

```text
confidence >= min_confidence
或
interest > 1
```

#### 候选产品得分

如果客户行为中出现了产品 A，则查找所有 `A → B` 规则。产品 B 的关联得分可以取相关规则置信度的最大值，避免重复行为造成不必要的放大。

### 7.3 加权最近邻算法

本项目不使用参考方案中的余弦相似度，而采用归一化后的加权曼哈顿距离：

```text
distance(x, y) = Σ wi × |xi - yi|
```

建议权重：

```text
风险匹配       0.30
投资期限       0.25
最低金额       0.20
产品类别       0.15
预期收益区间   0.10
```

数值特征使用：

```text
normalized_value = (value - min_value) / (max_value - min_value)
```

类别特征使用统一编码。新记录超出样例范围时：

1. 更新最大值或最小值；
2. 重新计算所有样例的归一化值；
3. 记录超出范围的字段；
4. 继续计算最近邻距离。

#### 距离阈值处理

```text
最小距离 <= 0.6：
    推荐相似样例关联的产品

最小距离 > 0.6：
    写入异常客户记录表
    标记为新样例候选
    推荐当前热门产品作为兜底
```

### 7.4 结果融合

先合并两种算法的候选产品，再进行去重和排序：

```text
final_score = 0.60 × association_score
            + 0.40 × similarity_score
```

关联得分和相似度都需要先归一化到 0 到 1。

冷启动时的处理：

```text
无历史行为：使用最近邻 + 热门产品
无有效关联规则：使用最近邻结果
最近邻距离 > 0.6：使用热门产品兜底
```

最终输出前 3 个产品，并为每个产品生成算法来源和中文推荐理由。

## 10. 测试与验证

- 支持度、置信度和兴趣度计算正确；
- 只有满足阈值的规则进入有效规则表；
- 购买数量变化不会改变二项关联结果；
- 归一化结果在预期范围内；
- 新值超出样例范围时会重新计算范围；
- 距离大于 0.6 时生成异常记录并触发热门产品；
- 不同客户的推荐结果存在差异；
- 风险等级不匹配的产品不会进入最终结果。

## 14. 原创性边界

为避免与参考 PPT 形成抄袭嫌疑，本项目遵守以下约束：

- 不复制参考 PPT 的文字、截图、流程图和页面布局；
- 不使用“余弦相似度 + 协同过滤”的原算法组合；
- 不实现参考 PPT 中的资产配置优化和实时股票价格模块；
- 使用二项关联规则和加权曼哈顿最近邻；
- 使用自己的产品数据、客户画像、数据库字段和推荐解释；
- 使用不同的页面结构、颜色和图表表达；
- 报告中如需说明参考来源，只描述借鉴了分层架构表达方式。

## 15. 风险与处理方式

| 风险 | 处理方式 |
|---|---|
| 行为数据太少，关联规则不足 | 增加模拟会话；使用最近邻和热门产品兜底 |
| 不同客户结果过于相似 | 调整画像、行为记录和风险过滤条件 |
| 新数据超过样例范围 | 重新计算最小值和最大值并记录异常字段 |
| 金融产品信息不完整 | 使用统一的产品字段和本地模拟数据 |
| 页面与算法联调困难 | 先固定 API JSON 格式，再开发前端 |
| 结果缺少解释 | 保存每个候选产品的算法来源和中间分数 |
